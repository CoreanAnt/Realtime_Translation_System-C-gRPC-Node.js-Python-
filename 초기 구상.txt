전체 시스템 구조도 (System Architecture)
이 시스템은 물리적으로 강사(Input), 중앙 서버(Processing), 학생(Output)의 3단계로 구성됩니다.

1. 강사 디바이스 (Input)
역할: 가벼운 발신자

기기: 강사 개인 노트북 (저사양 가능)

소프트웨어: Node.js (gRPC Client)

기능:

마이크 음성 수집

모드 결정 및 전송:

Local 모드: 음성 원본(Raw Data)을 그대로 중앙 서버로 전송.

Cloud 모드: gemini-2.5-flash-native-audio-preview-12-2025 모델과 직접 통신하여 번역된 결과(오디오+텍스트)를 중앙 서버로 전송.

2. 중앙 서버 (Processing Hub)
역할: 강력한 지휘 본부 및 연산 처리

기기: 고성능 데스크탑

소프트웨어 구성 (2가지 프로그램 구동):

A. 메인 서버 (C# .NET)

역할: 트래픽 관리 및 방송 송출 (Hub)

강사의 데이터를 수신하여 처리 경로를 분기함.

Local 모드일 경우: 내부의 Python 서버로 데이터 전달.

Cloud 모드일 경우: 즉시 학생들에게 데이터 방송.

접속한 다수의 학생 클라이언트 세션 관리.

B. AI 엔진 (Python FastAPI)

역할: 로컬 AI 연산 담당 (Worker)

사용 모델: NVIDIA Canary-Qwen-2.5B (음성 인식 및 번역/합성 통합 모델)

C# 서버로부터 받은 오디오를 처리하여 번역된 오디오와 텍스트를 반환.

3. 학생 디바이스 (Output)
역할: 수신자(하지만 여기서 특정 언어를 선택 하였을 경우 메인서버에 그 언어를 보내서 해당 언어로 오디오데이터를 줘야함)

기기: 학생 스마트폰 또는 태블릿 (Android / iOS / Windows)

소프트웨어: C# .NET MAUI

기능:

중앙 서버에 접속하여 스트림 대기.

청각: 수신된 오디오 데이터를 스피커로 재생.

시각: 수신된 텍스트 데이터를 화면에 자막으로 표시.

데이터 흐름 요약 (Data Flow)
1. 수집 단계

강사(Node.js)가 마이크에 대고 "오늘 수업 시작합니다"라고 말함.

2. 처리 단계 (분기)

Case A: Local 모드 (보안/오프라인 중시)

강사(Node.js)가 원본 음성을 보냄.

서버(C#)가 받아서 Python 서버로 넘김.

Python 서버가 Canary-Qwen-2.5B 모델을 사용해 번역 후 반환.

Case B: Cloud 모드 (자원 절약 중시)

강사(Node.js)가 gemini-2.5-flash-native-audio-preview-12-2025 API로 번역 수행.

번역 완료된 데이터를 서버(C#)로 보냄.

3. 송출 단계

서버(C#)가 접속해 있는 모든 학생(MAUI)에게 "Class starts today" (음성+자막)를 전송.
